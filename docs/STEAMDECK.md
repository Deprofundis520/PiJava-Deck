## 切换语言 / Change language

- 游戏列表顶部点击 EN / 中文 按钮可直接切换。
- 手柄：≡ → 设置管理 → 最后一项“语言 / Language”，按 A 或左右切换。游戏内从 ≡ → 显示设置进入同一页。
- 安装器：点击 English / 中文；选择会与模拟器共用。
- 自动保存至用户目录 `pijava/language.cfg`，内容为 zh 或 en。默认中文，切换立即生效，下次启动记忆。不会写入游戏配置或即时存档。

On the game list, click the language button at the top. With a controller, press Menu, scroll to the last Settings row (Language), then press A or Left/Right. In-game, open Menu → Display settings. The installer has an English / 中文 button too. Language is saved globally and takes effect immediately.

Extract the complete archive. Open PiJava to play, or Install to create/update desktop shortcuts. Open Add to Gaming Mode to submit the Steam shortcut using SteamOS; Steam can stay running. Keep romfs beside the executable.

将直接可用的 .jar 放入 PiJava-Deck/games；列表按 Y 刷新，L3 选择目录，A 正常启动，X 读取即时存档。升级前备份用户数据。

Put .jar games in PiJava-Deck/games. Y refreshes, L3 selects the folder, A starts a game, and X loads its save state. Back up your user data before upgrading. Commercial games are not bundled.

# PiJava Deck v3.13 使用与更新说明

这是基于 incuryou/PiJava 的 Steam Deck / SteamOS（Linux x86_64）实验移植版。支持桌面模式与 Steam 游戏模式。基于已综合适配的 FIT25 底座，本版新增内存修改；保留文字输入、游戏显示名修改、自定义遮罩；保留分辨率选择、横屏等比显示、手机机型按键兼容配置；保留中文菜单、遮罩、滤镜、按键映射、即时存档与游戏模式快捷方式。

## v3.13 更新：内存修改

游戏内按 **≡ → 内存修改**。支持 8/16/32/64 位整数的精确搜索、未知初值、变化筛选、单目标改值、锁定与撤销。全手柄数值输入，Y 切换正负号。具体步骤见随包《内存修改使用说明.md》。结果和锁定仅限当前运行，读档/重启清除，普通修改值可随即时存档保存。

v3.13 不改变 Java 类库布局或 J2S5 格式，沿用 v3.12 的 FIT25 底座、自动分辨率、画面旋转、自适应遮罩与现有 Deck 功能。已做主机回归及跨 v3.12 状态探针，未做 Deck 实机或 Linux JIT 执行验证。更早版本的即时存档仍保留此前兼容范围。

## 沿用 v3.10 的功能操作

游戏列表右上角的按钮现在叫“设置管理”。按 ≡ 也可直接进入。游戏内暂停菜单的“显示设置”同样进入这个管理页。设置共 **10 项**，向下滚动可找到“游戏改名”“自定义遮罩”和“画面旋转”。

### 1. 游戏文字输入

1. 在游戏中进入需要输入姓名、角色名、账号等文字的界面。
2. 若是 Form 表单，先用方向键把焦点移到要修改的 TextField 文字框。
3. 按 **≡ → 文字输入 → A**，打开文字编辑器。TextBox 也可用同样方法编辑。
4. 使用内置键盘，或系统键盘、输入法、剪贴板输入文字。
5. 按 **≡ 完成**，把整段文字写回游戏，自动返回游戏画面；按 **B 取消**则保留游戏原来的内容。
6. 若游戏还要求按自己的“确认 / 完成”软键提交，请回到游戏后再操作。宿主的“完成”只负责填写输入框。

| 编辑器操作 | 手柄 |
|---|---|
| 选择屏幕键盘上的字符 | 左摇杆 / 十字键 |
| 输入选中的字符 | A |
| 删除光标前一个字符 | X |
| 切换英文大小写 | Y |
| 左右移动文字光标 | L1 / R1 |
| 清空编辑内容 | 左侧视图键 |
| 写回游戏或保存名称 | 右侧 ≡ 菜单键 |
| 放弃编辑 | B |

屏幕下方也有退格、清空、空格、完成、取消按钮，可直接用鼠标或触摸点击。

外接键盘支持正常文字、退格、Delete、Home/End、Ctrl+A 全选、Ctrl+V 粘贴。未检测到手柄时，左右键移动文字光标，Enter 完成、Esc 取消；检测到手柄时，使用 ≡ 完成和 B 取消，避免 Steam 桌面按键模拟的 Enter/Esc 造成重复操作。此时外接键盘可用 Alt+左右移动文字光标。

中文可通过系统中文输入法提交，或从剪贴板粘贴；可用 Steam + X 呼出系统键盘。内置手柄键盘提供英文字母、数字和符号，**没有内置拼音词库**。中文能否直接键入取决于 SteamOS 的输入法与键盘配置；代码已接入 SDL 文字提交和输入法组合事件，但未做 Deck 实机输入法验证。

数字、电话号码、小数输入框会按游戏设置限制字符；密码输入框在编辑器中隐藏文字；只读输入框不能修改。最大长度采用游戏的 UTF-16 字符单位规则，宿主编辑器最多编辑 16384 个单位。取消时不会把草稿写入游戏。

**支持范围为标准 MIDP TextBox，以及 Form 当前选中的 TextField。** 通过 Canvas 自绘的取名键盘、游戏私有输入界面，本版不能直接识别；此时会提示未选中标准输入框，需继续使用游戏自己的输入方式。不会向游戏盲目发送整段文字按键。

### 2. 修改游戏显示名

1. 在游戏列表选中游戏，按 **≡**。
2. 向下找到 **游戏改名**，按 **A**。
3. 用同一个文字编辑器输入新名称，按 **≡** 保存；鼠标也可点击“完成”。
4. 返回列表立即显示新名称。清空名称后保存，可恢复原 JAR 文件名显示。

显示名最长 64 个 UTF-16 单位，不含换行或控制字符。这里修改的是模拟器中的显示名称，**不会改动实际 JAR 文件、游戏清单或存档身份**。同内容的 JAR 共用名称和游戏配置；移动或改名原文件后，仍按内容识别。

### 3. 导入自定义遮罩

1. 准备一张遮罩图片，推荐 **1280×720、8 位 PNG**。PNG 可以带透明区域，JPG/JPEG 也支持；原版 J2SJ `.skin` 可导入。
2. 先选中要设置的游戏，进入 **≡ → 自定义遮罩 → 导入图片**。
3. 在文件浏览器找到图片，按 **A** 打开。无需手动输入完整路径。
4. 进入预览页后，红框与蓝色占位区域表示游戏显示窗口。按方向上下选择 X、Y、宽度、高度，左右调整。
5. 按 **≡**，或选“应用并保存”后按 A。若这是当前正在暂停的游戏，遮罩会立即用于该游戏；否则在启动该游戏时使用。

也可以把图片直接放进程序旁的 **skins** 文件夹，在遮罩列表按 Y 刷新后选择。处于设置管理、遮罩列表或导入浏览器时，可以直接拖入图片。

| 预览页操作 | 功能 |
|---|---|
| 上下 | 选择 X、Y、宽度、高度或操作按钮 |
| 左右 | 每次调整 8 像素；按住会连续调整 |
| L1 / R1 | 每次微调 1 像素 |
| X | 恢复默认窗口：400、40、480、640 |
| Y | 窗口设为整个 1280×720 内容区域 |
| ≡ | 应用并保存 |
| B | 取消本次窗口调整，返回遮罩列表 |

默认窗口坐标为：左边距 400、上边距 40、宽 480、高 640。随包的 `skins/自定义遮罩模板.png` 已按这个窗口制作，不附加按键功能提示文字，可直接试用或作为制作素材。

图片会先等比放进 1280×720 背景，区域坐标按这个背景计算。窗口内部由游戏画面覆盖；游戏始终等比显示，剩余部分为黑边。预览页使用蓝色占位，并非运行中的游戏截图。透明区域在窗口外会合成黑色背景。

自定义遮罩对横屏游戏也生效：它使用你设置的窗口，不再自动套用内置竖屏手机遮罩。请为横屏选择合适的宽窗口；游戏本身仍须兼容所选虚拟分辨率。

素材导入后复制到用户数据目录的 `skins`，按内容 SHA-256 管理，原图片不会移动或删除。每个游戏分别保存所选遮罩；**同一张遮罩素材共用一套窗口坐标**。取消预览不会应用选择，但已经导入的素材仍可在遮罩库中找到。

要恢复内置遮罩，在自定义遮罩列表选择第一项“使用内置遮罩”；也可直接修改普通“遮罩”设置，这会取消当前所选游戏的自定义遮罩。其他游戏已有的自定义选择不受影响。

文件限制为 16 MiB，PNG/JPG 每边最多 4096 像素；PNG 使用现有解码器，RGB/RGBA 为 8 位，不能使用 16 位色深。SVG、WebP、APNG 动画和其他格式不在本版导入范围内。J2SJ `.skin` 维持原版容器的尺寸与负载限制。

### 4. 更新与备份

完整解压 v3.13 后运行“一键安装”，确认列表标题显示 **v3.13**。不要只替换某个旧启动入口。继续保留原来的 `games`，并备份用户数据中的 `rms`、`state`、`game-options`、`skins`。

v3.13 可读取 v1/v2 旧游戏配置；保存后使用 v3，增加每游戏旋转。请避免再用旧版本修改这份配置。已有游戏 JAR 与存档不会因为设置显示名而改名。

下面保留基础启动、分辨率、机型、按键映射与存档说明。

## 一、安装或更新

1. 将 `PiJava-Deck-点开即用-v3.13.tar.gz` 复制到 Deck，在桌面模式完整解压。
2. 打开解压后的 `PiJava-Deck` 文件夹，双击 `PiJava` 可直接运行；也可以双击 `一键安装` 更新固定安装目录和桌面入口。
3. 从旧版升级时，先关闭正在运行的模拟器，再运行新版 `一键安装`。旧桌面图标或旧脚本可能仍指向旧程序，更新后确认游戏列表标题为 **v3.13**。
4. 程序和 `romfs` 必须一起更新。不要只复制单个可执行文件；请保留配套的 `Canvas.class` 和完整资源。

正常情况下无需终端、系统镜像或安装 Java。若桌面管理器提示执行权限，可在文件属性 → 权限中允许作为程序执行。

固定安装目录通常为 `/home/deck/.local/share/pijava/app`。存档和配置保存在它的上一级用户数据目录，不随应用目录更新覆盖。若设置了 `XDG_DATA_HOME`，以该目录下的 `pijava` 为准。

升级前建议备份整个 `/home/deck/.local/share/pijava`，尤其是 `rms`、`state` 和 `game-options`。旧即时存档若提示版本不兼容，可正常启动游戏使用游戏自身的 RMS 存档；本版已测试新状态往返，未保证旧即时存档跨类库/挂起方法变更的兼容性。请保留 v3.11 与旧数据备份。

## 二、放入游戏并启动

1. 把直接可用的 `.jar` 文件放进解压目录的 `PiJava-Deck/games`。如你一直使用 `/home/deck/Desktop/java`，可以继续使用这个目录，不必改文件名。
2. 启动模拟器。如果列表没显示游戏，按 **L3（按下左摇杆）** 打开游戏目录选择器，找到实际放 JAR 的目录，按 **Y 使用此目录**。也可用鼠标点击“游戏目录”。
3. 返回游戏列表后，按 **Y** 刷新；左摇杆上下选择游戏，按 **A** 正常开始。
4. **X 继续** 用于读取该游戏已有的即时存档。第一次运行或要使用新分辨率、新机型配置时，请用 **A**。

`.zip`、`.rar`、`.7z` 需要先解压，不能把压缩包当作 JAR。随包不提供商业游戏。

## 三、选择分辨率

1. 在游戏列表先选中要设置的游戏。
2. 按右侧 **≡ 菜单键**，进入“设置管理”。
3. 用左摇杆上下选择“游戏分辨率”，用左右或 **A** 切换。更改后自动保存。
4. 按 **B** 返回游戏列表，再按 **A** 正常启动。

可选项：

| 方向 | 分辨率 |
|---|---|
| 默认 | 游戏旁的 `<文件名>.jar.screen` 设置；未设置时使用 240×320 |
| 自动识别 | 游戏声明、文件名等可识别线索；失败时回退，不保证所有 JAR 可识别 |
| 方屏 | 128×128、208×208、360×360 |
| 竖屏 | 128×160、176×200、176×205、176×208、176×220、240×260、240×320、240×400、320×480、352×416、360×640、480×800 |
| 横屏 | 320×240、400×240、480×320、640×360、640×480、800×480 |

“分辨率”指游戏看到的虚拟手机画布，不是 Deck 显示器分辨率。优先选与 JAR 原生版本一致的尺寸。不同内容的 JAR 独立保存设置；同一个 JAR 改名或移动目录后仍按内容识别。

游戏运行中也能通过 **≡ → 显示设置** 修改，但分辨率、机型都在下次 **A 正常开始** 时生效。返回当前游戏只会继续原画布，不会强行重启。重新开始前，请先在游戏内保存进度。

**X 或“读取即时存档”会恢复存档本身的画布尺寸**，不会套用新的分辨率。要确认刚改的尺寸，请返回列表用 A 开始，而不是 X 读档。

高级用户：显式 `--size 宽x高` 高于菜单选择；菜单的明确分辨率高于 `.jar.screen`。选择“默认”可恢复原有 sidecar 行为。仅选择“自动识别”才尝试识别；默认保持旧的 sidecar/240×320 行为。自动识别仍优先采用有效 sidecar；没有可靠线索时回退，尺寸冲突可能显示提示。

## 四、横屏等比显示

当画布宽度大于高度时，自动使用横屏布局，无需额外开关：

- 在 1280×720 内容区域内居中等比缩放，保留完整画面，不拉伸成竖屏，也不裁掉边缘。
- 自动暂时隐藏竖屏手机遮罩；下次打开竖屏游戏时恢复原遮罩选择。
- 原始、双线性、Scale2x、LCD、CRT、ScanlinesDX 滤镜使用同一个显示区域。
- 横屏画面不叠加右上角“菜单”文字按钮，按 **≡** 打开菜单；原有右上角触摸菜单热区仍保留。帧数可在设置中关闭。
- Deck 1280×800 屏幕仍有内容区域外的上下边带；本版没有把手机虚拟画布直接变成 1280×800。

按当前布局公式，320×240 会显示为居中的 960×720，400×240 为 1200×720，640×360 为 1280×720。其余空间保留黑边。这些是布局计算结果，未在 Deck 实机验证。

竖屏游戏也改为等比显示：有遮罩时放进原来的手机屏幕窗口；选择“无遮罩”时在内容区域内尽量放大。方屏游戏保持方形。

**支持横屏画布不等于所有竖屏游戏都能自动变为横屏。** 若游戏把坐标、图片、界面写死为 240×320，选择横屏可能出现空白或错位；请改回原生尺寸，或使用游戏本身的横屏 JAR 版本。本版没有修改游戏内部代码，也没有新增 J2ME 触屏游戏输入支持。

### 画面旋转与自适应遮罩

在设置管理最后一项“画面旋转”选择 0°、90°、180°、270°，按游戏保存。它只旋转最终图像，不改变游戏看到的宽高，也不旋转按键；需要时自行调整按键映射。当前暂停游戏的旋转立即生效。内置遮罩新增“自适应”；旧遮罩编号与自定义遮罩保留。

## 五、选择手机机型配置

在同一个“显示设置”菜单中选择“手机机型”，左右或 A 切换，自动按当前 JAR 保存，下次 A 正常开始生效。

| 配置 | 用途与键码 |
|---|---|
| 标准 / 诺基亚 | 保持旧版标准键码；软键 -6 / -7，确认 -5，数字及星号井号按标准字符键码发送。优先使用此项。 |
| 诺基亚横屏键盘 | 数字 1–9、*、0、# 对应 r、t、y、f、g、h、v、b、n、u、m、j 的键码，用于需要横屏字母键盘层的版本；软键与方向保持标准编码。 |
| 摩托罗拉 | 左右软键 -21 / -22、确认 -20；数字、星号、井号保持标准编码。 |

机型配置是**按键兼容预设**，并非完整手机硬件仿真，也不会自动改变分辨率、字体、厂商 API 或 `microedition.platform` 身份。分辨率与机型需分别选择。

处理顺序为：**Deck 物理按键 → 自定义手机按键映射 → 机型键码转换 → 游戏**。因此换机型时无需重绑 A/B/X/Y 等物理键；左摇杆仍固定控制方向。

`Canvas.getGameAction`、`getKeyCode`、`getKeyName` 与 GameCanvas 按键状态也接入相应转换；游戏内标准表单和命令菜单仍使用标准方向、软键控制。

## 六、修改按键映射

1. **≡ → 显示设置 → 按键映射 → A**。
2. 左侧先选手机目标键：左右软键、确认、数字 1–0、*、#。
3. 按 **≡**，出现“请按下要映射的按键”。
4. 按 Deck 上要分配的物理键，先松开，再按 **A** 确认。
5. 修改完毕后按左侧 **视图键（两个重叠方框）** 保存全部修改。仅按 B 返回会取消尚未保存的映射。

映射浏览页可按 **Y 清空映射草稿**，仍需视图键保存；B 可取消。左摇杆方向固定保留，不参与重新映射。该物理映射为全局配置；本版新增的分辨率和机型则按游戏分别保存。映射目标显示逻辑手机键名，机型转换在它之后进行。

## 七、即时存档与继续

游戏中按 **≡**，菜单有八项：返回游戏、显示设置、保存即时存档、读取即时存档、返回游戏列表、结束当前游戏、文字输入、内存修改。

- **返回游戏**：回到当前暂停的游戏，不会自动写入即时存档。
- **保存即时存档**：手动保存当前运行状态，看到保存成功提示后再退出。
- **读取即时存档**：恢复上次保存状态，会替换当前游戏进度。
- 游戏列表 **X 继续**：冷启动读取所选游戏的即时存档。
- 游戏列表 **B**：有当前暂停游戏时返回该游戏；没有游戏时退出。

v3.13 的即时存档保留保存时的画布尺寸，并另外记录保存时正在使用的机型，不受之后修改的设置影响。读取没有有效机型记录的旧存档时，使用旧版的标准机型。机型记录按存档内容 SHA-256 绑定，也能对应恢复到较早的备份存档。

备份或搬运时请一起保留 `state` 和 `game-options/snapshot-phones`，直接备份整个用户数据目录最方便。若提示“存档已保存，但机型记录失败”，请检查空间和目录权限；该存档读回时会使用标准机型。

RMS 是游戏自身的进度存储，与即时存档是两套机制。分辨率、机型配置不改变游戏的 RMS 身份。

## 八、常用操作与游戏模式

| 所在界面 | 操作 |
|---|---|
| 游戏列表 | 左摇杆上下选择，A 开始，X 读即时存档，L1/R1 翻页，Y 刷新，L3 游戏目录，R3 切换全屏 |
| 游戏列表 | ≡ 打开设置；可鼠标点击右上角设置或关闭按钮 |
| 游戏中 | ≡ 暂停菜单；视图键回到游戏列表；左摇杆方向控制 |
| 设置菜单 | 左摇杆上下选项，左右或 A 改值，B / ≡ 返回 |
| 按键映射 | 选择手机键，≡ 录入，松开后 A 确认，视图键保存 |

要添加到游戏模式，在解压目录双击 **添加到游戏模式**，或在“一键安装”里选择相应入口。沿用 v3.8 的 SteamOS 系统导入接口，**不要求退出 Steam**。缺少系统接口时打开 Steam 的“添加非 Steam 游戏”窗口，按界面提示选择 `PiJava`。提交后可在 Steam 库中确认；本版没有进行 SteamOS 实机导入验证。

建议在 Steam 为 PiJava 选择“游戏手柄”布局，让模拟器收到标准手柄输入。

## 九、数据位置与版本范围

默认用户数据目录：`/home/deck/.local/share/pijava`。

| 路径 | 内容 |
|---|---|
| `app/` | 固定安装的程序与资源 |
| `rms/` | 游戏自身存档 |
| `state/` | 即时存档与写入备份 |
| `game-options/<JAR-SHA256>.cfg` | 该游戏的分辨率、机型、旋转、显示名和遮罩选择 |
| `game-options/snapshot-phones/<存档-SHA256>.cfg` | 即时存档使用的机型记录 |
| `skins/` | 已导入的自定义遮罩原图与窗口配置 |
| `deck-keymap.cfg` | 全局物理按键映射 |
| `deck-menu.cfg` | 遮罩、滤镜、帧数等显示配置 |

本版完成 Linux x86_64 编译、链接和发布包检查；运行内存模块 VM 综合探针、8 组相关回归及一组跨 v3.12 状态验证，合计 10 组。v3.12 的 21 组 FIT25 底座测试是历史结果，不重复计入本版。没有执行发布的 Linux ELF、Linux JIT 或做 Steam Deck 实机验证。详细见《构建验证记录-v3.13.md》。
